# 内置 Edge 在线朗读设计

对应 [Issue #127](https://github.com/dengxibo/sumatrapdf-plus/issues/127)。用户在没有可用 WinRT / SAPI 语音、未安装 NaturalVoiceSAPIAdapter 的 Windows 环境中，也能在阅读器里选择 Edge 在线声音并朗读。新安装默认使用系统本地声音。升级时保留本地语音与本地双语配置。

## 入口与数据发送

- 在「设置 → 朗读」的现有声音模式中增加「Edge 在线声音」，列表显示名称和语言，支持试听。移除依赖适配器的「在线智能双语」「在线多语种」入口。为内置 Edge 声音单独保存服务语音 ID，避免与 SAPI token 混用。语音 ID 失效时提示重新选择。
- 选择在线模式时显示「朗读时，当前文字和紧接着要读的文字会发送给 Microsoft 语音服务」。启用前要求明确确认，切回本地后取消所有未完成的在线请求。开启设置页、启动应用和恢复标签页时均不主动联网。选择在线模式后才加载目录，试听发送内置示例。
- 启用时检查联网权限，每次发请求前再次检查。请求仅携带合成需要的文本、声音与语速。本文指当前朗读块及最多一个即将播放的块，数据仅在会话内存中留存。日志记录耗时、错误类型和字节数，避开正文、音频、书名和路径。
- 阅读入口、朗读条、从光标或选区开始的行为沿用现有界面。音色枚举和命令可用性独立于本地声音探测。EPUB 内录音和 PDF 页内音频继续走各自路径。查词的 TTS 发音跟随当前朗读方式：本地单声使用所选本地音色，本地双语按词语语言选声，Edge 使用所选在线多语种音色。启用说明补充「点击查词发音也会将待发音的词发送给 Microsoft」。Edge 直连、两种模式的查词发音及升级迁移须一起交付，再移除旧适配器在线路径。

## 中英文混排与选声

- **本地。** WinRT / SAPI 只提供本地声音，可选单声或「智能双语」。双语复用现有分段规则，中文句里的短英文通常跟随中文声，符合切换条件的英文句和长段用英文声。
- **Edge 在线。** 应用直连，用户只选一个通过中英混读验收的多语种音色。按标点和长度分块，尽量保留混排句上下文。播放中最多预取下一块。
- **SAPI 本地来源。** 核对 token 和已知适配器的来源元数据。现有按显示名称包含 Online / Multilingual 的判断只能作为分组线索。枚举、自动选声、系统默认解析和恢复保存的声音 ID 共用过滤规则。对具备联网能力的适配器验证离线 token 和内部回退行为，来源不明时排除该 token，并用出站记录验证本地模式。
- **旧在线设置迁移。** 旧适配器在线模式或 token 回退到系统本地声音，并提示可在设置中启用 Edge。缺少本地音色时显示选声入口。旧多语种音色有明确对应关系时可作为选声候选，启用新在线模式前由用户确认正文发送。

原型用中文夹缩写、独立英文句、长英文引文及纯英文验证候选多语种音色。

## 接入现有管线

### 菜单、工具栏和设置页

| 入口 | 调整 |
| --- | --- |
| **设置 → 朗读** | 将原先混列模式和音色的下拉框改为「朗读方式」，三个选项为「本地单声」「本地智能双语」「Edge 在线」。本地单声显示「系统默认」及可用的本地音色；智能双语显示中文、英文两个本地音色；Edge 显示一个多语种音色、正文发送说明和目录状态。试听本地双语时可分别听中英文，Edge 试听使用内置混排样句。目录加载失败时在音色旁提供重试；已有缓存音色可继续选择，首次使用无可用音色时提示先选择。高亮、跟随和书内录音设置放在公共区域。 |

| **底部朗读条** | 齿轮打开同一设置页。在线合成等待显示「正在缓冲」，允许立即暂停或停止；失败后显示「重试」并保留当前位置。有可用本地音色时可从提示切回本地。在等待时按下暂停，取消当前请求和预取，继续时从保留位置重新请求。倍速、跟随和上一句／下一句沿用现有操作。书内录音仍显示对应的录音播放控件。 |

设置页先编辑草稿，「应用」后才提交方式和音色。取消或关闭页面时终止试听、丢弃草稿。菜单快捷切换与设置页应用调用同一个逻辑，更新持久配置、当前会话和所有入口的选中状态。音色目录刷新仅在获准选择 Edge 后触发；菜单渲染和设置页初始化使用当前状态，无需等待网络。没有本地音色时，设置入口仍可用，工具栏可将用户引导到 Edge 设置。联网权限受限时，Edge 选项显示禁用原因。

实现时核对 `BuildReadAloudMenuItems`、`HandleReadAloudMenuSelection`、`ReadAloudSettingsPageInit/Apply`、`Toolbar.cpp` 的按钮状态和 `ReadAloudBar.cpp` 的齿轮及播放控件。同一方式在各入口的可用性和选中结果应一致，切换后的缓存、音频和高亮按会话身份统一失效。补齐菜单与设置页的中英文翻译、键盘操作及高 DPI 布局验收。

### 主题与布局发布验收

- 适配 Warm、White、Dracula、Black。设置页、顶部朗读菜单和底部朗读条分别沿用相邻原生控件的主题、字体、边框和交互样式。验证默认、悬停、按下、选中、键盘焦点和禁用状态，检查下拉列表及缓冲、错误提示的可读性。设置页和朗读条打开时切换主题，检查颜色立即刷新及控件尺寸稳定。
- 同类下拉框使用一致的行高、字体、内边距与对齐规则，按钮遵循设置页现有尺寸，朗读条图标使用一致的视觉尺寸和点击区域。三种模式切换时使用固定的音色区域和状态区域，避免试听按钮和公共设置上下跳动。中英文长标签与长音色名称在有限宽度下按控件规则换行或省略，下拉列表仍可查看完整名称。
- 缓冲、播放、暂停、失败、重试及跟随状态切换时，为播放控件和状态文案预留空间。验证按钮中心位置、朗读条边界和文本基线稳定，文案切换和长名称均无裁切、遮挡或重叠。窄窗口沿用朗读条现有的控件收起顺序，并核对播放和停止仍可访问。
- 用中英文界面跑四种主题的人工验收，覆盖最小支持窗口宽度、100% / 125% / 150% / 200% 缩放，以及不同 DPI 的主副屏之间往返移动。重点复测工具栏扬声器、底栏倍速和「跟随」在跨屏返回后是否放大。对模式切换、在线状态切换和跨屏返回记录前后截图；重复切换时现场检查抖动。出现尺寸不一致、重叠、错位或抖动时修复后重验。

每个朗读会话和文本块都有独立身份。所有音频和边界事件须匹配当前会话与文本块才能生效。停止、跳转、变速、换声或关闭所属文档时立即废弃旧会话，取消网络请求并清空缓存。暂停沿用现有位置恢复语义，暂停期间不继续请求新块。变速从当前文本位置按新速率重新合成。断网或限流时保留位置，提供「重试」和「切换到本地声音」（有可用声音时）。中途失败时从最后确认播到的位置恢复，避免重播整块或跳过剩余文字。

播放中最多预取下一块，确保选区结束或可读内容结束后停止提交。高亮用实际音频播放位置驱动，并把服务返回的边界匹配回合成文本，再映射到原文 UTF-8 字节位置。核对重复词、中英混排、标点、转义和发音替换。没有可靠词边界时显示句级高亮，播放完成以音频输出结束为准。比较「首块接收完成再播」和「边收边播」的延迟后决定解码方式，先用真实长文测量再扩大实现范围。

## 实施顺序与发布验收

### 2026-11-18 直连接口探测

从当前开发环境访问 Edge 的语音目录，使用不携带凭据的 GET 请求，收到 HTTP 401。请求只探测目录，未发送文档正文。上游 edge-tts 当前实现使用 Edge 专用客户端标识和 Sec-MS-GEC，属于浏览器服务的客户端验证。此结果将原生直连的待验证项收敛到第三方访问方式。 [edge-tts 客户端实现](https://github.com/rany2/edge-tts/tree/master/src/edge_tts)

Microsoft 公开支持 Edge 网页通过 SpeechSynthesis 使用在线声音。可做应用内 WebView2 探针，检查目标运行时是否实际枚举远程多语种声音、播放内置混排样句以及返回文本边界。浏览器文档本身无法确认 WebView2 的行为。原生客户端公开接口是 Azure Speech，需要用户配置语音资源和凭据。这会改变「直接选音色即可开读」的产品条件。 [Edge 在线语音策略](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/configureonlinetexttospeech) [Azure Speech REST API](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech)

后续确认采用原生 WinHTTP 路线。已新增响应解析、传输、SSML 请求构造及测试工具。运行 `out/dbg64/test_util.exe --edge-speech-probe out/edge-speech-probe.mp3` 会尝试合成内置中英混排样句。可通过 `SUMATRA_EDGE_PROBE_RESOURCE` 和 `SUMATRA_EDGE_PROBE_HEADERS` 在测试进程中提供服务授予的连接参数。默认探针在 WebSocket 升级阶段收到 HTTP 401，样句未发送，也未生成 MP3。正文朗读接线的下一项验收是成功升级并获取非空 MP3 与词边界。

### 阅读器实测

首次界面试读用的是系统默认声音。启动时的本地语音校验清除了已保存的 Edge 模式，该轮结果作废。修复方式是把 Edge 模式标识纳入启动设置解析，保留已保存的选声。显式启用 Edge 后，原 1024 字节分块能完成 HTTP 101 握手，但遇到了 30 秒接收上限。缩到 480 字节并将整轮接收上限调到 120 秒后，使用 Emma Multilingual 在 1× 连续取得了四块音频。

对隔离测试进程做 WASAPI 回环采样，按 −55 dB 阈值测得两个完整块间空档为 36.94 秒和 37.42 秒。逐样本的纯零间隔为 36.70 秒和 37.14 秒，说明大部分空档是播放等待。当前整块合成结束后才开始播放，下一块在上一块播放完成后才发起。后续应优先验证边收边播及有限预取对首音和块间空档的改善。

加入单块预取后，用同一份混排文档和 Emma Multilingual 1× 复测。播放当前块时启动下一块，切换时按文本和语速复用准备结果；停止或跳转会取消旧任务。日志中两次切换的下一块均已就绪。用播放日志中的 PCM 长度定位分块边界，WASAPI 录音在边界附近测得约 0.44 秒和 0.49 秒低于 −55 dB 的间隔。界面确认跨到第 2 页后高亮仍推进，停止后朗读条和高亮清除。第一块仍等完整合成，后续需验证流式解码与首音。

同机对照使用已安装的 NaturalVoiceSAPIAdapter，显式选择 EmmaMultilingual Online，通过标准 SAPI 把同一条中英样句输出到文件。合成耗时 2869 ms，得到 22050 Hz、16 位、5.445 秒的 WAV，PCM 为 240140 字节，峰值为 21848。确认已有适配器在当前环境可以使用该在线音色。对照验证了音频合成，未测词边界或原生探针认证。

随后从 TtsApplication 的集成目录移植了 v2 源码及其许可证，直接编入原生测试探针。由现有项目提供连接配置，探针通过 WinHTTP 直连 Microsoft，HTTP 101，耗时 2266 ms，返回 32688 字节 MP3 和 12 个匹配正文位置的词边界。此验证使用 EmmaMultilingual 合成同一条中英样句。下一步在阅读器正文路径接入音色选择、音频播放和取消，并用长文复测逐词高亮。

1. **原型验证。** 用公开示例文本验证声音枚举、中英混读、首音耗时、跨块衔接、取消和系统代理。Edge 社区客户端可流式获取音频及词边界，公开资料未提供面向第三方的 Edge 接口稳定性承诺。发布前核对第三方接入和分发条件。若直连不适合随产品发布，可单独评估需要用户配置凭据的 Azure Speech；该选项的配置成本与直接选择 Edge 声音不同。[edge-tts 项目](https://github.com/rany2/edge-tts)
2. **端到端接入。** 先实现选声、试听、开始、暂停恢复、停止、失败重试，再接单块预取和词级高亮。通过混读听测收敛 Edge 多语种音色列表。
3. **验收。** 在没有可用本地 TTS 和没有适配器的环境中验收安装后直选、试听和播放。用 PDF、EPUB、OCR 文本及混排长文验证选区边界、跨页衔接和停止。覆盖请求中停播、快速跳句、变速、换声、关标签、断网、超时、限流和声音下架。验证本地朗读、查词和录音回归，并检查未启用、暂停、停播和受限模式下的出站请求。
4. **记录测量结果。** 原型记录首音耗时与段间额外静音的 P50/P95，覆盖正常网络和有延迟的网络。用本地朗读作为段间静音的对照，结合实际样本定发布阈值。功能门槛是停止或切换后无旧音频和高亮，恢复时能从可见且合理的位置继续，失败时界面能解释原因并允许用户操作。
