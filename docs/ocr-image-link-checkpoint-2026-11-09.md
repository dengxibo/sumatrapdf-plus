# OCR 选字与图片链接

## 行为

图片上的 OCR 文字优先选字，单击识别文字不触发整张图片的链接。图片没有文字的位置和普通文字链接保留跳转能力，均在松开鼠标后处理。拖动后回到起点、拖到文字框外、取消手势均不触发跳转。

原先链接已经在 mouse-up 跳转并有拖动阈值；本次修正 mouse-down 的优先级，并在整次手势中保存 OCR 选字状态。鼠标悬停 OCR 文字与图片链接重叠处显示选字指针，隐藏底层链接提示。

只读取现有 OCR 文本缓存，不在鼠标移动时启动 OCR 或提取页面文字。图片链接通过图片和链接的页面边界识别：链接覆盖图片完整边界时让位于 OCR；普通文字链接的局部边界保持原有行为。不同来源的边界允许 0.5 页面单位的舍入差异。没有 OCR 文字缓存的页面保持原行为，不新增设置。

## 回归入口

格式化修改的 C/C++ 文件后运行 `bun ./cmd/build.ts`，然后运行 `python tools/test_ocr_image_links.py`（依赖 PyMuPDF、Pillow）。

脚本生成带图片链接及普通文字链接的 PDF、EPUB，通过 `SUMATRA_TEST_OCR_IMAGE_LINKS` 启动原生集成测试。固定 OCR 结果注入正常的引擎文本缓存，避免识别模型差异；测试实际 canvas 鼠标消息处理与正文导航，不修改用户书籍。

每个文档覆盖：OCR 文字单击、拖动选字、拖动返回起点、图片空白处点击、没有 OCR 缓存标记时点击、普通文字链接点击、取消手势、拖到文字框外松开、没有中间 mouse-move 消息而在远处松开。核对按下不跳转、文字选择路径、最终跳转结果，以及不跳转时导航历史不变。结果位于 `out/ocr-image-links`。

这些测试验证交互，不验证 OCR 模型的识别精度；未对用户实际漫画运行识别。本阶段不提交或发版。
